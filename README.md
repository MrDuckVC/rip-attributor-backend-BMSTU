# Backend системы атрибуции анонимного текста — ЛР3

Система предназначена для атрибуции анонимного текста по частотности служебных слов. Услуги каталога — **корпусы текстов потенциальных авторов** (`Corpus`, `corpora`). В ЛР3 используются два тематических показателя: количество слов `word_count` и процент местоимений `pron_percent`. Фильтрация — по минимальному количеству слов. Расчёт атрибуции и заявки в этой лабораторной не реализуются.

Стек: Go 1.25.3+, Gin, PostgreSQL, GORM, MinIO. API возвращает JSON и демонстрируется через Postman/Insomnia. Шаблонов и JavaScript в приложении нет.

## Запуск

Из корня проекта:

```bash
cp .env.example .env  # только если .env ещё не создан
# Укажите свои параметры в .env.
docker compose up -d
go run ./cmd/migrate
go run ./cmd/attributor
```

API: `http://localhost:8080/api`. Консоль MinIO: `http://localhost:9001`. SQL-клиент Adminer: `http://localhost:8082` (сервер `postgres`). Для показа API браузер не требуется.

Настройки `.env`: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASS`, `DB_NAME`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`. Дополнительные настройки MinIO: `MINIO_ENDPOINT` (по умолчанию `localhost:9000`), `MINIO_BUCKET_NAME` (`corpora`), `MINIO_USE_SSL` (`false`). Параметры сервера остаются в `config/config.toml`.

Миграция обновляет существующие таблицы, переносит старый признак `is_delete=true` в статус «удален», удаляет столбцы `prep_percent`, `conj_percent`, `is_delete` и добавляет ограничения уникальности. Таблицы не пересоздаются. Если в старых данных есть несколько черновиков одного пользователя или повторные лайки, миграция завершается ошибкой: данные автоматически не удаляются. Миграцию можно запускать повторно.

Текущий пользователь ЛР3 зафиксирован: `currentuser.Get()` всегда возвращает константу ID `1`. Функция находится в `internal/app/currentuser/currentuser.go`. Миграция сохраняет существующего пользователя с этим ID; при его отсутствии создаёт `test` / `test123`. Регистрация другого пользователя не меняет текущего. Настоящая авторизация — задача ЛР4.

## HTTP-методы

| Метод | URL | Входные данные | Успех |
|---|---|---|---|
| GET | `/api/corpora` | `query` — минимальное количество слов; `page` — страница от 1 | 200, список |
| GET | `/api/corpora/feed` | Без ID — первый корпус; `id` — конкретный; `id=…&next=true` — следующий | 200, один корпус |
| GET | `/api/corpora/draft` | Без ID; черновик текущего пользователя | 200, один корпус |
| POST | `/api/corpora` | `multipart/form-data`, поля и файлы ниже | 201, созданный черновик |
| PUT | `/api/corpora/:id/publication` | Без тела или пустой JSON `{}` | 200, пустое тело |
| DELETE | `/api/corpora/:id` | Без тела или пустой JSON `{}` | 200, пустое тело |
| POST | `/api/corpora/:id/like` | JSON `{"like":1}` или `{"like":0}` | 200, состояние лайка |
| POST | `/api/users` | JSON `{"login":"student","password":"test123"}` | 201, пользователь |
| POST | `/api/users/login` | Без тела либо JSON с `login`, `password`; заглушка | 200, пустое тело |
| POST | `/api/users/logout` | Без тела или `{}`; заглушка | 200, пустое тело |

Каталог содержит только опубликованные записи, по 6 на страницу, упорядоченные по ID. Отсутствие `query` отключает фильтр; пустой или некорректный фильтр — 400. Ответ списка: `{"items":[],"total":0,"page":1}`. Каждый элемент `items` использует сериализатор корпуса.

Лента выбирает основную запись непосредственно в БД с ограничением в одну строку. Порядок — возрастание ID. После последней записи выбирается первая опубликованная. `next` принимает `true`/`false` и используется только с `id`; при `false` возвращается сам корпус. Если опубликованных записей нет, ответ 404.

### Создание и переходы состояния

В форме создания разрешены только следующие текстовые поля:

| Поле | Значение |
|---|---|
| `author` | Обязательное имя автора, до 50 символов |
| `source` | Обязательное название источника, до 100 символов |
| `description` | Описание; без значения — пустая строка |
| `word_count` | Целое число от 0 до 2147483647 (тип integer в БД); без значения — 0 |
| `pron_percent` | Число от 0 до 100; без значения — `null` |

Файловые поля: `image` (JPEG, PNG, GIF, WebP), `video` (MP4, WebM). Они необязательны для черновика; для демонстрации передаются оба файла. Подготовьте **короткое вертикальное видео под формат телефона** по указанию преподавателя. Тип файла проверяется по содержимому, а не по имени или присланному Content-Type. Передача URL или обычного текста вместо файлов отклоняется.

Имена файлов генерируются как латинская шестнадцатеричная строка с расширением. Новые записи хранят **имена объектов** в `image_url`, `video_url`; сами файлы — в MinIO. В JSON сервер формирует подписанные URL со сроком действия 1 час, поэтому публиковать бакет для чтения не требуется. Старые URL из записей ЛР2 продолжают возвращаться как есть; новые загрузки всегда сохраняются по именам.

Допустимые переходы: создание → «черновик»; «черновик» → «опубликован» через PUT; «черновик» или «опубликован» → «удален» через DELETE. Вернуть опубликованную или удалённую запись в черновик нельзя. Публиковать и удалять можно только свои корпуса. У пользователя не более одного черновика: это проверяется транзакцией с блокировкой и частичным уникальным индексом.

ID, статус, создатель, даты и имена объектов вычисляет сервер. Клиенту запрещено передавать системные поля для изменения. Неизвестные поля JSON и формы отклоняются. Успешный ответ на создание выдаётся после загрузки файлов и фиксации записи. При ошибке загрузки или сохранения транзакция откатывается, уже загруженные объекты удаляются.

### Сериализаторы

Список, лента, черновик и результат создания используют одинаковые поля корпуса:

```json
{
  "id": 1,
  "author": "Автор",
  "source": "Источник",
  "description": "",
  "word_count": 200,
  "pron_percent": 8.5,
  "image_url": "",
  "video_url": "",
  "creator": {"id": 1, "login": "test"},
  "is_owner": 1,
  "is_liked": 0,
  "likes_count": 0,
  "date_create": "2026-09-30T10:00:00Z",
  "date_finish": null
}
```

Все поля присутствуют всегда, даже если значение пустое. `is_owner` и `is_liked` — числа 0/1. `pron_percent` и `date_finish` могут быть `null`, пустые URL — `""`. `creator` — вложенный сериализатор пользователя, только `id` и `login`. Статус корпуса, пароль и признак модератора в ответах не передаются.

Лайк возвращает `{"is_liked":1,"likes_count":1}`. Значение 1 устанавливает лайк от текущего пользователя, 0 снимает. Повторный запрос с тем же значением не переключает состояние и не создаёт повторных записей. Лайк возможен только для опубликованных корпусов. Регистрация возвращает `{"id":2,"login":"student"}`; пароль хранится в виде bcrypt-хеша. Логин уникален, до 25 символов; пароль обязателен, до 72 байт.

### Ошибки

| Код | Причина |
|---|---|
| 400 | Некорректные ID/поля/файлы; попытка передачи системных полей |
| 403 | Публикация или удаление чужого корпуса |
| 404 | Запись или черновик отсутствует; запись удалена; корпус для ленты/лайка не опубликован |
| 409 | Второй черновик, повторная публикация или занятый логин |
| 500 | Ошибка PostgreSQL/MinIO или другая внутренняя ошибка |

Ошибки возвращают пустое тело. JSON-обёрток `status`, `message` нет. Внутренние ошибки записываются в журнал сервера. Заглушки входа и выхода не создают сессии, токены или cookies.

## Таблицы PostgreSQL

### `corpora` — корпусы текстов авторов

| Поле | Тип | Назначение |
|---|---|---|
| `id` | integer, PK | Генерируемый ID |
| `creator_id` | integer, FK → users.id, NOT NULL | Создатель |
| `image_url` | varchar(255), NULL | Имя файла изображения для новых записей |
| `video_url` | varchar(255), NULL | Имя файла видео для новых записей |
| `author` | varchar(50), NOT NULL | Автор текстов |
| `source` | varchar(100), NOT NULL | Источник |
| `word_count` | integer, NOT NULL, default 0 | Количество слов |
| `pron_percent` | real, NULL | Процент местоимений |
| `description` | text | Описание |
| `status` | varchar(20), NOT NULL | «черновик», «опубликован», «удален»; только в БД |
| `date_create` | timestamp, NOT NULL | Дата создания, задаётся сервером |
| `date_finish` | timestamp, NULL | Дата завершения формирования при публикации |

Частичный уникальный индекс `idx_one_draft_per_user` на `creator_id` для статуса «черновик». Удалённые записи сохраняются и не возвращаются клиенту.

### `users` — пользователи

| Поле | Тип | Назначение |
|---|---|---|
| `id` | integer, PK | Генерируемый ID |
| `login` | varchar(25), UNIQUE, NOT NULL | Логин |
| `password` | varchar(100), NOT NULL | bcrypt-хеш для новых пользователей |
| `is_moderator` | boolean, NOT NULL, default false | Существующее системное поле; регистрация не может его задать |

### `likes` — лайки

| Поле | Тип | Назначение |
|---|---|---|
| `id` | integer, PK | Генерируемый ID |
| `user_id` | integer, FK → users.id, NOT NULL | Пользователь |
| `corpus_id` | integer, FK → corpora.id, NOT NULL | Корпус |

Уникальный индекс `idx_user_corpus` по `(user_id, corpus_id)` исключает повторный лайк. Снятие лайка удаляет строку из `likes`; требование мягкого удаления относится к корпусам.
